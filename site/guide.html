Guide

How it works

On this page

DocWriter is a companion, not a word processor. The manuscript stays in the editor you already use; you paste one chapter at a time and the bible is built from that text. Everything is stored on your machine.

First run

On Windows, run the DocWriter-1.1.0-win-x64.exe installer, or unzip DocWriter-1.1.0-win-x64.zip to a folder and run the DocWriter.exe inside it. The build is not code-signed, so Windows shows “Windows protected your PC” the first time — choose More info then Run anyway.

On Linux, the AppImage runs without installing, and the .deb installs a launcher entry on Debian and Ubuntu.

chmod +x DocWriter-*.AppImage ./DocWriter-*.AppImage

SHA256SUMS.txt (opens in a new tab) on the release covers all four files, so a download can be checked before it runs.

First launch gives you an empty book, ready for a first chapter. There is nothing to sign in to: no account, no sync, and no network calls beyond the localhost port the app serves itself.

Your book is one file

A book is a single SQLite file — ~/.config/DocWriter/docwriter.db on Linux, %APPDATA%\DocWriter\docwriter.db on Windows. Chapters, cards, mentions and settings all live inside it. The About dialog names the file that is currently open.

Book → Open book… points the window at any .db file, so a book can be kept wherever you like and moved whenever you like.

Back up and export

Book → Export book file (.db) writes a full copy of the open book; on another computer, Book → Open book… opens that copy. Nothing is re-rendered or converted on the way, so everything travels. A snapshot is also saved into a backups/ folder beside the book once a day, and the last five are kept.

Book → Export as Markdown writes the book as Markdown for readers. Settings → Export writes Markdown too.

Keyboard

Triage and the reader are keyboard-first by design. Triage keys apply while the triage dialog is open; Alt+Left and Alt+Right move between chapters from anywhere in the app.

In triage

  • Enter Accept the name as shown.
  • 1–9 Accept the name as one of the five types.
  • ← → Change which type it will be accepted as.
  • L Later: the name waits in Review › New names.
  • X Ignore: the name stays silent, and Review › Rejected can restore it.
  • Esc Close triage.

These eleven are the app's own shortcuts, and each one can be changed in Settings → Keyboard. They are listed there in the same three groups.

Book

  • Ctrl+O Open book.
  • Ctrl+N New book.

Chapter

  • Ctrl+K Quick open.
  • Alt+Left Previous chapter.
  • Alt+Right Next chapter.
  • Ctrl+S Save chapter.

Window

  • Ctrl+= Zoom in.
  • Ctrl+- Zoom out.
  • Ctrl+0 Actual size.
  • F11 Full screen.
  • Ctrl+Q Quit DocWriter.

All eleven are listed under Settings → Keyboard, where each one can be rebound or put back to its default. A chord needs Ctrl, Alt or an F-key, and a combination already in use is refused with the name of the shortcut that owns it. Copy, paste, undo and reload are refused at the capture box, because shadowing them would break editing. Escape, Tab and the arrows inside a list belong to whatever has focus, and are not rebindable.

Known limits

  • The Windows build is unsigned, so SmartScreen warns once on first run. There is no macOS build yet, and no auto-update — each release is a fresh download.
  • The AppImage needs FUSE. Where FUSE is missing, --appimage-extract-and-run starts it anyway, and the .deb avoids the question entirely.
  • The desktop entry generated for the AppImage runs AppRun --no-sandbox %U. That is Electron's sandbox opted out of for desktop-launched runs — acceptable for an offline local app, and still what the file says.
